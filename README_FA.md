# SmarTel — ربات هوش مصنوعیِ مدیریت‌شدهٔ تلگرام بیزنس

**زبان‌ها:** [English](README.md) · فارسی (همین فایل)

SmarTel یک دستیار هوش مصنوعی از نوع **«ربات مدیریت‌شدهٔ تلگرام بیزنس»** است.
کاربرِ تلگرام بیزنس، ربات را از طریق مسیر داخلیِ تلگرام
(**Settings → Business → Chatbots**) به حساب شخصی/کاری خود متصل می‌کند. پس از
اتصال، ربات **پیام‌های خصوصیِ ورودیِ مشتریان** را دریافت می‌کند و می‌تواند
**به نمایندگی از حساب کاری** و با کمک هوش مصنوعی پاسخ دهد.

این ربات فقط از **قابلیت‌های رسمیِ Business در Telegram Bot API** استفاده می‌کند —
بدون ورود کاربرـربات (userbot) با Telethon/Pyrogram، بدون شماره تلفن/کد ورود/رمز
دومرحله‌ای/Session String و بدون اسکرپینگ. توکن ربات از **@BotFather** گرفته می‌شود.

---

## این ربات چه می‌کند

- 🤖 **پاسخ خودکار** به مشتریان، یا حالت **تأیید پیش از ارسال** (ربات پاسخ را
  پیشنهاد می‌دهد و شما **Send / Edit / Reject / Pause Chat** را می‌زنید).
- 🧩 **سه بک‌اندِ هوش مصنوعی:** **OpenAI API**، **اشتراک ChatGPT از طریق Codex CLI**،
  یا **هر اندپوینت سازگار با OpenAI** (مدل محلی / پراکسی).
- 📝 **دستورالعمل‌های سفارشی** (`/instructions`) — یک قانون ثابت که به هر پاسخ
  افزوده می‌شود (مثل زبان، لحن، شخصیت).
- 📚 **پایگاه دانش** (متن، `.txt`، `.md`، `.pdf`، `.docx`) برای مستندسازی پاسخ‌ها،
  همراه با **حالت سخت‌گیرانه (strict)** اختیاری.
- 🧠 **حافظهٔ مجزا برای هر مشتری**، ایزوله‌شده در هر گفت‌وگو.
- 🙋 **تحویل‌گرفتن توسط مالک**: وقتی خودتان به مشتری پاسخ می‌دهید، پاسخ خودکار برای
  آن گفت‌وگو به‌صورت خودکار متوقف می‌شود (پیش‌فرض ۳۰ دقیقه).
- 🚦 **محدودیت نرخ** برای هر مشتری (پیش‌فرض ۲۰ پیام در ساعت) با توقف خودکار.
- 🛡️ **لایهٔ ایمنی**: پیام‌های حساس (حقوقی / پزشکی / مالی / بازگشت وجه / عصبانیت /
  داده‌های شخصی / اطلاعات ورود) حتی در حالت خودکار هم به مسیر تأیید می‌روند.
- 🔒 **کنترل‌های فقط‌مالک**، لاگ‌گیریِ ساختاریافته با حذف اسرار، و مدیریت خطای
  مقاوم (یک پیام بد هرگز ربات را از کار نمی‌اندازد).

### ربات معمولی در برابر ربات مدیریت‌شدهٔ بیزنس

<div dir="ltr">

| | Normal bot | **SmarTel (Business managed bot)** |
| --- | --- | --- |
| Who messages it | Users chat the bot directly | Customers message **your account**; the bot acts on your behalf |
| How it connects | Users press *Start* | You connect it in **Telegram Business → Chatbots** |
| Update types | `message` | `business_connection`, `business_message`, `edited_business_message`, `deleted_business_messages` |
| Replies | from the bot | **from your business account** (via `business_connection_id`) |

</div>

اگر فردی غیر از مالک **مستقیماً** به ربات SmarTel پیام دهد، ربات فقط توضیح می‌دهد که
یک دستیار مدیریت‌شده است و در آنجا گفت‌وگو نمی‌کند.

## پیش‌نیازها

- **Python 3.10+** (روی 3.14 توسعه داده شده).
- یک حساب **تلگرام بیزنس**. قابلیت‌های Business نیازمند اشتراک **Telegram Premium**
  روی حسابی است که ربات را متصل می‌کند.
- یک **ربات** ساخته‌شده با **@BotFather** که **Business Mode** آن **فعال** است.
- یک بک‌اندِ هوش مصنوعی: یک **کلید OpenAI API**، **یا** **Codex CLI** واردشده به
  یک پلن ChatGPT، **یا** یک اندپوینت سازگار با OpenAI.

## ۱) ساخت ربات در BotFather

1. **@BotFather** را باز کنید → `/newbot` → یک نام و `@username` انتخاب کنید.
   **توکن** را کپی کنید.
2. فعال‌کردن Business Mode: `/mybots` → انتخاب ربات → **Bot Settings** →
   **Business Mode** → **Turn on**. (اگر ربات در Business Mode نباشد، تلگرام اجازهٔ
   اتصال آن به‌عنوان چت‌بات را نمی‌دهد.)
3. (توصیه‌شده) توضیحات/About را تنظیم کنید.

**شناسهٔ عددیِ کاربری** خود را از **@userinfobot** بگیرید (هر پیامی برایش بفرستید).
این شناسه، **مالک/ادمین** ربات است — فقط همین کاربر می‌تواند SmarTel را کنترل کند.

### انتخاب بک‌اندِ هوش مصنوعی

گام ۳ در جادوگر سه گزینه ارائه می‌دهد؛ `/status` همیشه بک‌اندِ فعال را نشان می‌دهد.

#### بک‌اند ۱ — کلید OpenAI API

`OPENAI_API_KEY` را (از `platform.openai.com`) تنظیم کنید. پرداخت به‌ازای مصرف؛
با مدل پیش‌فرض `gpt-4.1-mini` هزینه تقریباً چند سنت برای هر صد پیام است. بعداً هم
می‌توانید با `/connect_openai` آن را به‌روزرسانی کنید.

#### بک‌اند ۲ — اشتراک ChatGPT از طریق Codex (داخلی)

پاسخ‌ها را با **پلن ChatGPT** خود و از طریق **Codex CLI** رسمی («Sign in with
ChatGPT») تولید کنید — بدون کلید API و بدون پراکسی. در جادوگر انتخاب کنید:

> **3) AI backend → 2) Sign in with ChatGPT**

جادوگر وجود Codex CLI را بررسی می‌کند، **در صورت نبود آن را نصب می‌کند** (با `npm`
و در صورت نبود، با Homebrew)، **`codex login`** را برایتان اجرا می‌کند (مرورگر، یا
`--device-auth` برای ماشین‌های بدون رابط گرافیکی) و `MODEL_BACKEND=codex` را تنظیم
می‌کند. سپس هر پاسخ با اجرای `codex exec` (با ابزارها/سندباکس غیرفعال) و احرازِ
هویتِ ورودِ شما تولید می‌شود.

راه‌اندازی دستی به‌جای جادوگر:

<div dir="ltr">

```bash
npm install -g @openai/codex      # or: brew install --cask codex
codex login                       # choose "Sign in with ChatGPT"
```

</div>

کلیدهای مرتبط در `.env`: `MODEL_BACKEND=codex`، و به‌صورت اختیاری `CODEX_MODEL`
(مثلاً `gpt-5.4`؛ خالی = مدل پیش‌فرض Codex)، و گزینه‌های پیشرفتهٔ `CODEX_BIN`،
`CODEX_EXEC_TIMEOUT`، `CODEX_EXEC_ARGS`.

**نکات مهم:** Codex یک *عاملِ کدنویسی* است، بنابراین پاسخ‌ها از فراخوانیِ API کندترند
و لحن ممکن است متفاوت باشد؛ **محدودیت‌های نرخِ پلن ChatGPT اعمال می‌شود**؛ و در این
بک‌اند **امبدینگ (embeddings) در دسترس نیست** (بخش [پایگاه دانش](#پایگاه-دانش) را
ببینید). این روش (Codex CLI رسمی + ورود رسمیِ ChatGPT) قانونی است، اما خودکارسازیِ
یک اشتراک شخصی برای سرویس‌دهی به مشتریان، یک ناحیهٔ خاکستری از نظر سیاست‌های استفاده
است — شرایط OpenAI را بررسی کنید.

#### بک‌اند ۳ — اندپوینت سفارشیِ سازگار با OpenAI

`OPENAI_BASE_URL` را تنظیم کنید تا SmarTel به هر سرور سازگار با OpenAI وصل شود:

- **مدل محلی (بدون هزینه):** Ollama → `http://localhost:11434/v1`،
  LM Studio → `http://localhost:1234/v1`. مقدار `openai_model` را (در `/settings`)
  برابر نام مدل محلی بگذارید؛ اگر سرور به کلید نیاز ندارد، `OPENAI_API_KEY` را خالی
  بگذارید.
- **ارائه‌دهندهٔ دیگر:** هر base URL سازگار با OpenAI به‌همراه کلید همان ارائه‌دهنده.
- **پراکسیِ متکی بر اشتراک:** اگر ترجیح می‌دهید ورودِ ChatGPT خود را با یک پراکسیِ
  ثالثِ سازگار با OpenAI سرویس‌دهی کنید، `OPENAI_BASE_URL` را به آن پراکسی اشاره
  دهید (راه‌اندازی و نگهداری با شماست).

## ۵) اتصال ربات در تلگرام بیزنس

روی **حسابی که از دستیار استفاده می‌کند**:

1. تلگرام → **Settings** را باز کنید.
2. **Telegram Business** → **Chatbots**.
3. `@username` ربات را وارد کنید.
4. اجازهٔ **پاسخ‌دادن** به پیام‌ها را بدهید و انتخاب کنید به **کدام چت‌ها** دسترسی
   داشته باشد.
5. **Save.**
6. از یک حساب **دیگر** تلگرام، به حساب کاری پیام بدهید تا تست شود.

پس از اتصال، SmarTel مقدار `business_connection_id` را ذخیره و به شما اطلاع می‌دهد.
برای تأیید از `/status` استفاده کنید (نشان می‌دهد اتصال اجازهٔ پاسخ دارد یا نه).

## تنظیمات

به‌صورت زمان‌اجرا از طریق `/settings` قابل ویرایش‌اند (مقادیر بولی همان‌جا تغییر
می‌کنند؛ اعداد/فهرست‌ها یک صفحهٔ فرعی باز می‌کنند). در SQLite ذخیره می‌شوند و در
اجرای نخست یک‌بار از `.env` مقداردهی اولیه می‌گردند.

<div dir="ltr">

| Setting | Default | Meaning (شرح) |
| --- | --- | --- |
| `openai_model` | `gpt-4.1-mini` | مدلِ چت (بک‌اندهای OpenAI / اندپوینت سفارشی) |
| `temperature` | `0.4` | دمای نمونه‌برداری |
| `max_tokens` | `800` | بیشینهٔ توکن خروجی |
| `auto_reply_enabled` | `false` | ارسال خودکار پاسخ‌ها |
| `approval_mode_enabled` | `true` | پیشنهاد پاسخ برای تأیید پیش از ارسال |
| `kb_enabled` | `true` | استفاده از پایگاه دانش |
| `strict_kb_mode` | `false` | پاسخ **فقط** از روی پایگاه دانش |
| `memory_enabled` | `true` | حافظهٔ گفت‌وگو برای هر مشتری |
| `owner_takeover_pause_minutes` | `30` | مدت توقف پس از پاسخ دستیِ شما |
| `sensitive_requires_approval` | `true` | اجبار به تأیید برای موضوعات حساس |
| `monitoring_mode` | `true` | اطلاع‌رسانی دربارهٔ فعالیتِ ورودی/خودکار |
| `max_messages_per_customer_per_hour` | `20` | محدودیت نرخ برای هر مشتری |
| `public_direct_bot_chat_enabled` | `false` | پرچم ایمنی برای پیام‌های مستقیم (غیر‌بیزنس) |
| `process_nontext_enabled` | `false` | پردازش کپشن مدیا (نه فقط متن) |
| `custom_instructions` | *(خالی)* | دستورالعمل ثابتِ افزوده‌شده به هر پاسخ (با `/instructions`) |

</div>

**ایمن به‌طور پیش‌فرض:** با `auto_reply_enabled=false` و `approval_mode_enabled=true`،
هیچ چیزی تا زمانی که خودتان اقدام نکنید به مشتری نمی‌رسد. هر وقت آماده بودید
`/auto_on` را روشن کنید.

## دستورالعمل‌های سفارشی (شخصیت و زبان)

دستور `/instructions` یک قانون ثابت تعیین می‌کند که **همیشه به پرامپتِ سیستمی**
هر پاسخ افزوده می‌شود — جای درست برای زبان، لحن یا شخصیت. برخلاف پایگاه دانش، این
دستور وابسته به بازیابی (retrieval) نیست، پس همیشه و روی **همهٔ** بک‌اندها (از جمله
Codex) اعمال می‌شود.

<div dir="ltr">

```text
/instructions Your name is Charisma. You are from Iran. Always answer in Persian (فارسی).
/instructions            # show the current instruction
/instructions clear      # remove it
```

</div>

> برای **رفتار** (زبان/شخصیت) از `/instructions` و برای **حقایق** از **پایگاه دانش**
> استفاده کنید. قراردادنِ «همیشه فارسی پاسخ بده» در پایگاه دانش **کار نمی‌کند** —
> متنِ پایگاه دانش، زمینهٔ اختیاری و وابسته به بازیابی است، نه یک فرمان.

---

## پایگاه دانش

- متن اضافه کنید (`/kb_add`) یا فایل `.txt` / `.md` / `.pdf` / `.docx` بارگذاری کنید
  (`/kb_upload`).
- فایل‌ها از نظر حجم بررسی، پسوندشان در فهرست مجاز کنترل، نامشان پاک‌سازی، در
  `storage/uploads/` ذخیره و **هرگز اجرا نمی‌شوند**. متن استخراج و تکه‌تکه (chunk)
  می‌شود.
- **بازیابی:** امبدینگ‌های OpenAI (`text-embedding-3-small`) به‌صورت JSON در SQLite
  ذخیره و با **شباهت کسینوسی** (numpy) رتبه‌بندی می‌شوند، و در نبودِ امبدینگ به‌طور
  خودکار به **جست‌وجوی کلیدواژه‌ای** برمی‌گردد.
- **میان‌بُرِ پایگاه دانشِ کوچک:** اگر کل پایگاه دانش کوچک باشد (حداکثر ۱۲ تکه)،
  **تمام** آن به پرامپت افزوده می‌شود و خودِ مدل پرسش را به حقایق شما ربط می‌دهد.
  این کار باعث می‌شود تعداد کمی حقیقت حتی بدون امبدینگ هم قابل‌اتکا باشند.
- **حالت سخت‌گیرانه** (`strict_kb_mode`): اگر چیز مرتبطی پیدا نشود، به مشتری گفته
  می‌شود *«اطلاعات کافی دربارهٔ این موضوع در پایگاه دانش ندارم.»* و مدل اصلاً
  فراخوانی نمی‌شود. برای پرسش‌وپاسخِ عمومی این حالت را **خاموش** نگه دارید.

**امبدینگ + بک‌اند Codex.** امبدینگ همیشه از مسیر OpenAI انجام می‌شود، در حالی که
چت می‌تواند از مسیر Codex باشد. پس برای یک پایگاه دانشِ **بزرگ** روی بک‌اند Codex،
هم `OPENAI_API_KEY` و هم `MODEL_BACKEND=codex` را تنظیم کنید: بازیابیِ پایگاه دانش
از امبدینگ‌های OpenAI (بسیار ارزان) استفاده می‌کند و پاسخ‌ها همچنان از اشتراک
ChatGPT شما می‌آیند. مواردی که **پیش از** در دسترس‌بودن کلید اضافه شده‌اند بدون
امبدینگ ذخیره شده‌اند (فقط کلیدواژه‌ای) — برای امبدینگ‌شدن دوباره اضافه‌شان کنید.

---

## حالت تأیید

وقتی حالت تأیید روشن است (یا پیامی حساس تشخیص داده شود)، ربات کارتی برایتان ارسال
می‌کند شامل نام/شناسهٔ چتِ مشتری، پیام او و پاسخ پیشنهادی، به‌همراه دکمه‌ها:

- **Send** → پاسخ از طریق اتصال بیزنس ارسال می‌شود.
- **Edit** → متن ویرایش‌شده را به‌عنوان پیام بعدی بفرستید؛ همان ارسال می‌شود.
- **Reject** → پاسخ دور انداخته می‌شود.
- **Pause Chat** → خودکارسازی برای آن مشتری متوقف می‌شود.

تأییدها idempotent هستند (در برابر چندبار زدن محافظت‌شده). اگر مشتری پیام اصلی را
حذف کند، تأیید به‌طور خودکار لغو می‌شود. جریانِ Edit در برابر ری‌استارت مقاوم است
(در پایگاه‌داده ذخیره می‌شود، نه در حافظه).

---

## تحویل‌گرفتن توسط مالک

وقتی شما (مالک حساب کاری) **خودتان** به مشتری پاسخ می‌دهید، تلگرام آن پیام را به
ربات هم می‌دهد. SmarTel این را تشخیص می‌دهد
(`message.from_user.id == connection owner id`) و **پاسخ خودکار** را برای آن چت به
مدت `owner_takeover_pause_minutes` (پیش‌فرض ۳۰) **متوقف** می‌کند. همچنین می‌توانید
به‌صورت دستی با دکمهٔ تأیید یا `/pause_chat` / `/resume_chat` توقف/ادامه دهید.

---

## محدودیت نرخ و مدیریت پیام‌های حساس

- **محدودیت نرخ:** یک پنجرهٔ متحرکِ یک‌ساعته برای هر مشتری
  (`max_messages_per_customer_per_hour`، پیش‌فرض ۲۰). در صورت عبور، پاسخ خودکار آن
  مشتری یک ساعت متوقف می‌شود و به شما اطلاع داده می‌شود.
- **مدیریت پیام حساس:** اگر پیامی با یک دستهٔ حساس مطابقت داشته باشد (حقوقی، پزشکی،
  مالی، بازگشت وجه، عصبانیت/تهدید، داده‌های شخصی، اطلاعات ورود) و
  `sensitive_requires_approval` روشن باشد، پاسخ حتی در حالت خودکار هم به مسیر تأیید
  می‌رود.

## نکات امنیتی

- ربات **هرگز** شماره تلفن، کد ورود، رمز دومرحله‌ای یا Session String شما را
  نمی‌خواهد. فقط از اتصال رسمیِ Business در Bot API استفاده می‌کند.
- دسترسیِ فقط‌مالک روی همهٔ دستورات، کال‌بک‌ها و تأییدها.
- اسرار از لاگ‌ها حذف می‌شوند؛ توکن کامل / کلید OpenAI / گفت‌وگوهای مشتری جز در حالت
  `DEBUG=true` لاگ نمی‌شوند.
- نسخهٔ ذخیره‌شدهٔ کلید OpenAI در صورت تنظیم `SMARTEL_FERNET_KEY` با Fernet رمزنگاری
  می‌شود. فایل‌های `.env`، `*.db` و بارگذاری‌ها در git نادیده گرفته می‌شوند.
- به‌طور پیش‌فرض ایمن — تا زمانی که خودتان فعال نکنید چیزی خودکار ارسال نمی‌شود.

## تست سرتاسری

1. `python main.py` را اجرا کنید و به‌عنوان مالک `/start` بفرستید.
2. یک بک‌اند پیکربندی کنید (کلید API با `/connect_openai`، یا انتخاب Codex در جادوگر).
3. (اختیاری) `/instructions Always reply in Persian.` و افزودن حقایق با `/kb_add`.
4. `/approval_on` و `/auto_on` را فعال کنید.
5. ربات را در **Telegram → Settings → Business → Chatbots** متصل کنید.
6. از یک حساب دیگر به حساب کاری پیام بدهید.
7. کارتِ پاسخ پیشنهادی را می‌گیرید → **Send** را بزنید؛ مطمئن شوید مشتری پاسخ را
   **از حساب کاریِ شما** دریافت می‌کند.
8. خودتان به مشتری پاسخ دهید و مطمئن شوید پاسخ خودکار برای آن چت متوقف می‌شود.

## رفع اشکال

- **هندلرهای Business اجرا نمی‌شوند** ← ربات باید با انواع آپدیتِ Business در
  `allowed_updates` کار کند (SmarTel این کار را می‌کند). همچنین مطمئن شوید ربات در
  Business → Chatbots **اجازهٔ پاسخ** دارد (`/status` در غیر این صورت `read-only`
  نشان می‌دهد).
- **اتصال ربات در تنظیمات Business ممکن نیست** ← **Business Mode** را در @BotFather
  فعال کنید و مطمئن شوید حساب **Telegram Premium** دارد.
- **خطای «Invalid token» در شروع** ← `BOT_TOKEN` را بررسی کنید (`python main.py --reset`).
- **هر پاسخ می‌گوید «اطلاعات کافی ندارم…»** ← **حالت سخت‌گیرانهٔ پایگاه دانش** روشن
  است؛ در `/settings` خاموشش کنید (در این حالت فقط از روی پایگاه دانش پاسخ می‌دهد).
- **ربات یک حقیقتِ پایگاه دانش را نادیده می‌گیرد** ← روی بک‌اند Codex امبدینگ وجود
  ندارد، پس بازیابی فقط کلیدواژه‌ای است؛ پایگاه دانشِ کوچک (≤ ۱۲ مورد) همیشه افزوده
  می‌شود، اما برای پایگاه دانشِ بزرگ‌تر `OPENAI_API_KEY` را برای امبدینگ تنظیم کنید.
  برای زبان/شخصیت از `/instructions` استفاده کنید، نه پایگاه دانش.
- **خطای فلگِ `codex exec`** (`unexpected argument …`) ← SmarTel به‌طور خودکار با
  مجموعهٔ فلگِ حداقلی دوباره تلاش می‌کند؛ اگر ادامه داشت، `CODEX_EXEC_ARGS` را در
  `.env` برابر فلگ‌هایی بگذارید که نسخهٔ Codex شما می‌پذیرد و از موفقیت `codex login`
  مطمئن شوید.
- **هیچ پاسخی تولید نمی‌شود** ← `/status` را ببینید (*AI backend: ready*)؛ کلید را با
  `/connect_openai` دوباره اضافه کنید، `openai_model` را بررسی کنید، یا از ورود
  Codex مطمئن شوید.
- **مالک پیام‌ها را دریافت نمی‌کند** ← `OWNER_USER_ID` را بررسی و یک‌بار به ربات
  `/start` بدهید.
- **PDF اضافه شد ولی متنی نیامد** ← PDFهای اسکن‌شده/تصویری پشتیبانی نمی‌شوند (بدون OCR).

## یادداشت‌های فنی

- **فریم‌ورک:** `pyTelegramBotAPI` (TeleBot) که به‌صورت بومی از هندلرهای Business و
  پارامتر `business_connection_id` پشتیبانی می‌کند (≥ 4.17.0 / Bot API 7.2). HTTP خام
  (`telegram_api.py`) فقط برای `getBusinessConnection` (که wrapper پایدار در همهٔ
  نسخه‌ها ندارد) و به‌عنوان fallback استفاده می‌شود.
- **ذخیره‌سازی:** SQLite (با WAL، اتصالِ thread-local و یک قفلِ نوشتن برای مدلِ
  polling چندنخی).
- **هوش مصنوعی:** SDK رسمی پایتونِ OpenAI (چت + امبدینگ، مقاوم در برابر تفاوت
  `max_tokens` و `max_completion_tokens`)؛ به‌علاوه بک‌اند اختیاریِ Codex CLI از طریق
  `codex exec`.

ساختار پروژه: `main.py`، `config.py`، `database.py`، `telegram_api.py`،
`keyboards.py`، `security.py`، `utils.py`، `handlers/`، `services/`، `storage/`.
